Seu mouse quebrou.
A interface ainda precisa te obedecer.

Para quem navega só com o teclado — por deficiência motora, lesão temporária ou porque o mouse simplesmente parou de funcionar — cada Tab é um passo. Se um componente prende o foco ou o esconde, a pessoa fica presa dentro da própria página. Este projeto mostra como resolver isso de verdade.

Por que foco de teclado importa

A acessibilidade web atende quatro perfis centrais. Este squad assume a responsabilidade pelo segundo: garantir que ninguém dependa de um mouse para operar a interface.

01

Leitores de tela

NVDA, JAWS, VoiceOver — dependem de aria-expanded e aria-controls para descrever o que está acontecendo.

02

Navegação por teclado

Foco em .focus(), focus trap e suporte a Tab / Esc. É o perfil deste projeto.

03

Cognição e atenção

TDAH, autismo, dislexia — comportamento previsível (como fechar com Esc) reduz carga mental.

04

Situacional

Braço engessado, mouse quebrado, sol forte na tela. Sem deficiência permanente, mesma barreira.

O problema

Um componente sem controle de foco é uma armadilha

Quando um modal, menu lateral ou carrossel aparece na tela e o JavaScript não move o foco para dentro dele, o usuário de teclado continua tabulando pelo conteúdo atrás do componente — invisível, mas ainda focável. Ele erra o alvo, se perde, e em muitos casos nem sabe que o componente foi aberto.

Pior: se o foco escapa para fora de um modal ativo, a pessoa pode acionar botões que estão escondidos atrás dele sem perceber. E sem uma tecla de saída rápida como Esc, cancelar a ação vira um teste de paciência.

  • ✕ Foco continua "atrás" do componente aberto
  • ✕ Tab leva a pessoa para fora da tela, sem retorno
  • ✕ Nenhuma forma de cancelar sem usar o mouse
  • ✕ Ao fechar, o foco se perde no topo da página

A solução

Três comportamentos, implementados de verdade

.focus()

Foco direcionado

Ao abrir o componente, o JavaScript move o foco imediatamente para o primeiro elemento interativo dentro dele — nunca deixa o usuário "solto".

⇥ ⇄

Focus trap

Enquanto o componente está ativo, Tab e Shift+Tab circulam apenas entre os elementos internos. O resto da página fica temporariamente fora do percurso.

Esc

Saída garantida

Pressionar Esc fecha o componente a qualquer momento e devolve o foco exatamente para o botão que o abriu.

Como testar

Roteiro de teste sem mouse

  1. 1

    Guarde o mouse

    Literalmente. Use apenas Tab, Shift + Tab, Enter / Espaço e Esc.

  2. 2

    Chegue até o botão da demo

    Use Tab a partir do topo da página até focar em "Excluir conta de teste" e pressione Enter.

  3. 3

    Tente escapar do modal

    Continue pressionando Tab várias vezes. Note que o foco nunca sai do modal — ele circula entre os botões internos.

  4. 4

    Cancele com Esc

    Pressione Esc. O modal fecha e o foco volta exatamente para o botão que você usou para abri-lo.

  5. 5

    Repita no menu lateral

    Faça o mesmo percurso no botão "Abrir menu lateral" e confira o aria-expanded mudando de false para true nas ferramentas de desenvolvedor.
